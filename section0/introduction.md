# イントロダクション

『すごいHaskellたのしく学ぼう！』（原著: Learn You a Haskell for Great Good!）のイントロダクションの要約。

## Haskell とは何か

### 純粋関数型

- 命令型言語は「どう計算するか」の手順を並べる。関数型言語は「それが何であるか」を定義する。
  - 例: 階乗は「1 から n までの積」、リストの和は「先頭の要素と残りの和を足したもの」。
- 変数に一度値を束縛したら、あとから別の値に変えられない。

#### 純粋関数が保証すること

1. **同じ引数で呼べば、必ず同じ結果が返る。** 結果は引数だけで決まる。現在時刻、グローバル変数、呼び出す順番や回数には左右されない。関数は内部に状態を保持しない。
2. **副作用を持たない。** 関数にできるのは、計算して結果を返すことだけ。変数の書き換えや画面への出力を、関数の中でこっそり行わない。

この 2 つがそろうと、関数呼び出しをその結果の値に置き換えても、プログラムの意味が変わらない（参照透過性）。

#### 純粋であることのメリット

1. **関数の正しさを推論しやすい。** 関数の振る舞いは引数だけで決まるので、読むときにその関数の中だけを見ればよい。「どこかで変数が書き換えられていないか」を追いかけなくて済む。
2. **小さな関数を組み合わせて、大きな関数を作れる。** 正しい関数どうしをつないだ結果は、互いに干渉しないので正しいままである。
3. **テストしやすい。** 事前の状態づくりが要らない。引数を渡して、返り値を確かめるだけで済む。
4. **計算の順番や回数を、処理系が自由に決められる。** いつ計算しても、何回計算しても結果が同じなので、計算を後回しにできる。次の節の遅延評価は、この性質の上に成り立つ。

1 と 2 は原著が挙げているメリット。3 と 4 は、同じ性質から導かれる一般的な利点として補った。

### 遅延評価

- 結果が必要になるまで、関数の実行も計算も行わない。
- 参照透過性があるので、プログラムを「データに対する変換の連なり」として扱える。
- 無限に続くデータ構造も扱える。
- 例: `xs = [1,2,3,4,5,6,7,8]` に対する `doubleMe(doubleMe(doubleMe(xs)))`
  - 命令型言語なら、リストを 3 回走査してコピーを作ることになる。
  - 遅延評価では、結果を要求されたときに初めて計算が走る。最初の要素を求められたら、その要素について 3 つの `doubleMe` が順に働く。結果としてリストの走査は 1 回で済む。

<details>
<summary>通常の言語との違いを、例で詳しく見る</summary>

違いは「いつ計算するか」にある。通常の言語は書いた時点で全部計算し、Haskell は結果が必要になった分だけ計算する。

#### 通常の言語（Ruby の例）

```ruby
def double_me(xs) = xs.map { |x| x * 2 }

xs = [1, 2, 3, 4, 5, 6, 7, 8]
result = double_me(double_me(double_me(xs)))
```

内側の呼び出しから順に、その場で最後まで実行される。

1. 1 回目の `double_me` が 8 要素すべてを 2 倍して、新しい配列 `[2, 4, ..., 16]` を作る。
2. 2 回目がその配列を全部たどって `[4, 8, ..., 32]` を作る。
3. 3 回目がまた全部たどって `[8, 16, ..., 64]` を作る。

リストを 3 回走査し、途中の配列も 2 つ作る。`result` を結局使わなかったとしても、この計算は済んでしまっている。

#### Haskell

```haskell
doubleMe xs = map (* 2) xs

xs = [1, 2, 3, 4, 5, 6, 7, 8]
result = doubleMe (doubleMe (doubleMe xs))
```

この行を書いた時点では、何も計算されない。`result` は「`xs` を 3 回 2 倍したもの」という約束として置かれるだけである。

誰かが「最初の要素をください」と言ったときに初めて動く。

1. 外側の `doubleMe` が、真ん中の `doubleMe` に「最初の要素をください」と頼む。
2. 真ん中が内側に、内側が `xs` に同じことを頼む。
3. `xs` が `1` を渡し、内側が `2`、真ん中が `4`、外側が `8` にして返す。

1 つの要素が 3 つの `doubleMe` を通り抜けて出てくる。2 番目の要素は、求められるまで手つかずのまま残る。

#### 違いがはっきり出る例

「最初の 2 個だけ欲しい」場合。

```haskell
take 2 (doubleMe (doubleMe (doubleMe xs)))   -- [8, 16]
```

Haskell は 2 要素分しか計算しない。残りの 6 要素は一度も 2 倍されない。Ruby の書き方では、8 要素を 3 回ぶん計算したあとで 2 個を取り出す。

これを極端にしたのが「無限に続くデータ構造」である。

```haskell
take 3 (doubleMe [1 ..])   -- [2, 4, 6]
```

`[1 ..]` は 1 から無限に続くリスト。通常の言語で「無限のリストを全部 2 倍する」と書くと終わらないが、Haskell は求められた 3 個分しか計算しないので、すぐに答えが返る。

#### たとえると

- 通常の言語は作り置きの食堂。注文が入る前に、全員分の料理を 3 工程すべて済ませておく。
- Haskell は注文を受けてから作る店。1 皿頼まれたら、その 1 皿だけを 3 工程通して出す。頼まれなければ何も作らない。

#### 補足

Ruby にも `xs.lazy.map { ... }.first(2)` のように遅延評価を使う書き方はある。通常の言語では明示的に頼んだときだけ遅延になり、Haskell では何も書かなくても最初からすべてが遅延になる。

</details>

### 静的型付け

- コンパイル時に、どの式がどの型かが決まっている。数と文字列を足すような誤りは、コンパイルの段階で検出される。
- 型推論を備えているので、すべての式に型を書く必要はない。`a = 5 + 4` と書けば、`a` が数であることはコンパイラが導く。
- 型推論のおかげで、コードを汎用的に書きやすい。

<details>
<summary>型推論と動的型付けの違いを、例で詳しく見る</summary>

どちらも「型を書かなくていい」ので似て見えるが、型がいつ決まり、誤りがいつ見つかるかが違う。

- 型推論では、型は実行前（コンパイル時）に決まる。書かなかった型はコンパイラが代わりに割り出すので、型は省略されているだけで存在する。
- 動的型付けでは、型は実行中にその場の値を見て調べる。コードの段階では、変数にも式にも型が決まっていない。

#### 誤りが見つかるタイミング

数と文字列を足す誤りを、めったに通らない分岐の中に書いたとする。

Ruby（動的型付け）:

```ruby
def price_label(n, rare_case)
  if rare_case
    n + "円"      # 数 + 文字列。誤り
  else
    n.to_s
  end
end

price_label(100, false)  # 問題なく動く
price_label(100, true)   # ここで初めて TypeError
```

`rare_case` が `true` になる日まで、誤りに気づけない。テストでその分岐を通していなければ、本番で初めて落ちる。

Haskell（静的型付け + 型推論）:

```haskell
priceLabel n rareCase =
  if rareCase
    then n + "円"
    else show n
```

型は 1 つも書いていないが、コンパイラが「`n + "円"` は数と文字列の足し算だ」と割り出し、コンパイルの時点でエラーにする。その分岐を一度も実行しなくても見つかる。

#### 変数の扱い

Ruby では、同じ変数に違う型の値を入れ直せる。型は変数ではなく、値のほうに付いているからである。

```ruby
a = 5 + 4     # 整数
a = "hello"   # 文字列を入れ直せる
```

Haskell では `a = 5 + 4` と書いた時点で `a` は数と決まり、文字列として使えばコンパイルエラーになる。

#### ghci で確かめる

型推論の結果は `:t` で見られる。

```haskell
ghci> :t "hello"
"hello" :: String
ghci> :t not True
not True :: Bool
```

書いていない型が、ちゃんと決まっているのがわかる。

#### まとめ

| | 型推論（Haskell） | 動的型付け（Ruby など） |
|---|---|---|
| 型が決まる時 | コンパイル時 | 実行時 |
| 型の誤りが見つかる時 | 実行前、全コードについて | その行を実行した時 |
| 型を書く必要 | ほぼない | ない |
| 変数に別の型を入れ直す | できない | できる |

型推論は「静的型付けの安全さ」と「型を書かない手軽さ」を両立させる仕組みである。静的型付けでも、昔の Java のように型推論が弱い言語では、型を毎回書く必要があった。

</details>

### 簡潔さ

- 高水準の概念を多く使うため、同じ処理を命令型言語で書いた場合よりもプログラムが短くなることが多い。
- 短いプログラムは保守しやすく、バグも入りにくい。

## 始めるために必要なもの

- テキストエディタと Haskell コンパイラ。
- コンパイラは GHC（Glasgow Haskell Compiler）を使う。最も広く使われている処理系。
- GHC はスクリプト（拡張子 `.hs`）をコンパイルできるほか、対話モード `ghci` を持つ。
  - `ghci` と入力して起動する。
  - `:l myfunctions` で `myfunctions.hs` に定義した関数を読み込む。
  - スクリプトを書き換えたら、もう一度 `:l myfunctions` するか `:r` で再読み込みする。
- 基本的な進め方は、`.hs` ファイルに関数を定義し、`ghci` に読み込んで試し、ファイルを直してまた読み込む、の繰り返し。
