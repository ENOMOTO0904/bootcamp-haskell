# 1.6 タプル

『すごいHaskellたのしく学ぼう！』第 1 章「はじめの第一歩」の 1.6 節の要約。

## タプルとは

- **タプル**は、複数の値を 1 つにまとめたものである。丸括弧で囲み、要素をカンマで区切って書く。
- リストとの違いは 2 つある。

| | リスト | タプル |
|---|---|---|
| 要素の型 | すべて同じ型 | 違う型を混ぜられる |
| 型を決めるもの | 要素の型だけ。長さは関係ない | 要素の数と、それぞれの型 |
| 書き方 | `[1,2,3]` | `(1,"a",True)` |

- 何個の値をまとめるかが、あらかじめ決まっているときに使う。
- 名前と年齢のように、種類の違うデータをまとめられる。

```haskell
("Christopher", "Walken", 55)
```

<details>
<summary>なぜタプルが必要なのか（原著外の補足）</summary>

違う種類の値を、決まった数だけ、ひとまとめにして運びたい場面があるからである。Haskell のリストには同じ型しか入れられないので、別の入れ物が要る。

```
リスト  [ 数 ][ 数 ][ 数 ] ...    同じ種類を、いくつでも
タプル  ( 文字列 , 数 )            違う種類を、決まった数だけ
```

必要になる場面は 3 つある。

1. **関数から 2 つの値を返したい。** 関数が返せる値は 1 つだけなので、商と余りのように結果が 2 つあるときは、タプルにまとめて返す。

```haskell
ghci> divMod 7 2
(3,1)
```

2. **関係のある値を、ばらばらにしたくない。** 座標の x と y、名前と年齢のように、セットで意味を持つ値を 1 つにまとめる。
3. **2 つのものを対応づけたい。** 「この番号はこの果物」のような対応を、1 組として表す。`zip` の結果がこれに当たる。

「何でも入るリスト」にしなかったのは、型の誤りを実行前に見つけるためである。タプルは「1 つ目は文字列、2 つ目は数」という形を型として持つので、取り出した値の型がコンパイル時に決まる。

Ruby は実行時に型を調べるので、配列 1 つで両方の役割をこなせる。`7.divmod(2)` も、配列 `[3, 1]` を返す。

</details>

## 要素の数も型の一部である

- 平面上の点をリストで表すと、`[[1,2],[8,11,5],[4,5]]` のように、要素が 3 つある誤った点が混ざっても通ってしまう。
- タプルで表せば、この誤りはコンパイル時に見つかる。要素が 2 つのタプル（**ペア**）と 3 つのタプル（**トリプル**）は別の型なので、1 つのリストに混ぜられない。

```haskell
ghci> [(1,2),(8,11,5),(4,5)]
（型エラー。ペアのリストにトリプルが混ざっている）
```

- 要素の数が同じでも、型が違えば別の型になる。`[(1,2),("One",2)]` も型エラーになる。
- 大きさごとに型が違うので、「どの大きさのタプルにも要素を足せる関数」は書けない。
- 要素が 1 つだけのタプルはない。中の値そのものと変わらず、使い道がないからである。
- タプルは、要素どうしを比較できれば比較できる。ただしリストと違い、大きさの違うタプルどうしは比較できない。

<details>
<summary>タプルのリストに入れられるもの（原著外の補足）</summary>

タプルのリストでは、すべての要素が同じ形のタプルでなければならない。同じ形とは、要素の数が同じで、同じ位置に同じ型があることをいう。

```haskell
[("apple", 100), ("orange", 80), ("cherry", 300)]   -- OK。全部 (文字列, 数)

[("apple", 100), ("orange", 80, True)]   -- NG。数が違う
[("apple", 100), (80, "orange")]         -- NG。順番が違う
[("apple", 100), ("orange", "80")]       -- NG。2 つ目の型が違う
```

これは、2 つの決まりを組み合わせた結果である。

1. リストには、同じ型の要素しか入れられない。
2. タプルの型は、要素の数と、それぞれの型で決まる。

固定されるのは 1 つ 1 つのタプルの形だけで、リストの長さは自由である。列の数と型が決まっていて、行はいくつでも足せる表と同じ形になる。

```haskell
ghci> :t [("apple", True), ("orange", False)]
[("apple", True), ("orange", False)] :: [(String, Bool)]
```

`[(String, Bool)]` は、「`(String, Bool)` というペアのリスト」と読む。

</details>

## ペアを扱う関数

| 関数 | 働き | 例 | 結果 |
|---|---|---|---|
| `fst` | ペアの 1 つ目の要素 | `fst (8,11)` | `8` |
| `snd` | ペアの 2 つ目の要素 | `snd ("Wow", False)` | `False` |

- `fst` と `snd` はペア専用である。トリプルやそれより大きいタプルには使えない。

## zip で 2 つのリストをペアにする

- `zip` は、2 つのリストの同じ位置にある要素どうしをペアにして、ペアのリストを作る。
- 2 つのリストの要素の型は違っていてもよい。

```haskell
ghci> zip [1,2,3,4,5] [5,5,5,5,5]
[(1,5),(2,5),(3,5),(4,5),(5,5)]
```

- 長さが違うときは、短いほうに合わせて、長いほうの残りを捨てる。

```haskell
ghci> zip [5,3,2,6,2,7,2,5,4,6,6] ["im","a","turtle"]
[(5,"im"),(3,"a"),(2,"turtle")]
```

- 遅延評価のおかげで、無限リストと有限のリストも組み合わせられる。

```haskell
ghci> zip [1..] ["apple", "orange", "cherry", "mango"]
[(1,"apple"),(2,"orange"),(3,"cherry"),(4,"mango")]
```

## 直角三角形を見つける

タプルとリスト内包表記を組み合わせて、次の条件をすべて満たす直角三角形を探す。

- 3 辺の長さはすべて整数
- 各辺の長さは 10 以下
- 周囲の長さは 24

1. まず、各辺が 10 以下の三角形をすべて作る。

```haskell
triangles = [ (a,b,c) | c <- [1..10], a <- [1..10], b <- [1..10] ]
```

2. 直角三角形だけに絞る。`a` は斜辺 `c` 以下、`b` は `a` 以下とし、三平方の定理を条件に足す。

```haskell
rightTriangles = [ (a,b,c) | c <- [1..10], a <- [1..c], b <- [1..a], a^2 + b^2 == c^2]
```

3. 周囲の長さが 24 という条件を足す。

```haskell
ghci> rightTriangles' = [ (a,b,c) | c <- [1..10], a <- [1..c], b <- [1..a], a^2 + b^2 == c^2, a+b+c == 24]
ghci> rightTriangles'
[(8,6,10)]
```

- **解の候補をまず全部作り、それを加工し、条件で絞り込んで答えにたどり着く。** これは関数型プログラミングでよく使う進め方である。

## タプルと Haskell の特徴の関係

<details>
<summary>タプルは静的型付けと型推論のもとでどう働くのか（原著外の補足）</summary>

タプルは、意味のあるひとまとまりの値を、1 つの型としてくくる入れ物である。「名前と年齢」というまとまりは、`(String, Integer)` という 1 つの型になる。この型が、静的型付けと型推論のもとで次のように働く。

### 静的型付けとの関係: 形の誤りを実行前に見つける

静的型付けは、型の誤りをコンパイル時に見つける仕組みである。タプルは「何個の値が、どの順番で、どの型で並ぶか」を型として持つので、その形に関する誤りがすべて実行前に見つかる。

**1. 取り出した値の型が、実行前にわかる。**

```haskell
person = ("Walken", 55)
```

```haskell
ghci> snd person + 1
56
ghci> fst person + 1
（型エラー。1 つ目は文字列なので、数を足せない）
```

`person` の型は `(String, Integer)` である。コンパイラは、1 つ目が文字列で 2 つ目が数だと知っている。だから、名前に 1 を足すという誤りを、実行する前に止められる。

**2. 要素の数の誤りが、実行前にわかる。**

2 つのベクトルを足す関数を考える。

```haskell
addVectors a b = (fst a + fst b, snd a + snd b)
```

```haskell
ghci> addVectors (1,2) (8,11)
(9,13)
ghci> addVectors (1,2) (8,11,5)
（型エラー。ペアを渡すべきところにトリプルを渡している）
```

Ruby の配列で同じ関数を書くと、3 つ目の要素は黙って無視されるか、足りない要素が `nil` になって実行時にエラーになる。Haskell では、要素の数が合わない呼び出しそのものが書けない。

**3. 関数が何を返すかが、型でわかる。**

```haskell
ghci> :t divMod
divMod :: Integral a => a -> a -> (a, a)
```

末尾の `(a, a)` は、「同じ型の値を 2 つまとめたペアを返す」という意味である。呼び出す側は、結果が必ず 2 つあり、どちらも数であることを、実行しなくても知ることができる。「片方が返ってこないかもしれない」と心配する必要がない。

### 型推論との関係: 型を書かなくても形が伝わる

型推論は、書かなかった型をコンパイラが割り出す仕組みである。タプルの型は長くなりがちだが、ほとんどの場合、自分で書く必要がない。

**1. タプルを書くだけで、型が決まる。**

```haskell
ghci> :t person
person :: (String, Integer)
```

`("Walken", 55)` と書いただけで、「文字列と整数のペア」という型が付く。

**2. タプルを使う関数の型も、割り出される。**

```haskell
ghci> :t addVectors
addVectors :: (Num a, Num b) => (a, b) -> (a, b) -> (a, b)
```

`addVectors` の定義には、型を 1 つも書いていない。それでもコンパイラは、中で `fst` と `snd` と `+` を使っていることから、「数のペアを 2 つ受け取り、数のペアを返す関数」だと割り出した。先ほどトリプルを渡してエラーになったのは、この推論された型と合わなかったからである。

**3. タプルを作る関数や取り出す関数は、どんな型にも使える。**

```haskell
ghci> :t fst
fst :: (a, b) -> a
ghci> :t zip
zip :: [a] -> [b] -> [(a, b)]
```

`a` や `b` は「どんな型でもよい」という意味である。`fst` は、中身が何であってもペアの 1 つ目を返す。`zip` は、どんな型のリスト 2 つからでもペアのリストを作る。実際に使うと、中身に合わせて型が決まる。

```haskell
ghci> :t zip [1,2,3] "abc"
zip [1,2,3] "abc" :: Num a => [(a, Char)]
```

数のリストと文字列を渡したので、結果は「数と文字のペアのリスト」になった。

### ほかの特徴との関係

| 特徴 | タプルとの関係 |
|---|---|
| 静的型付け | 直接の関係がある。違う型をまとめつつ、型を実行前に確かめるために、形を型として持つ入れ物が必要になった |
| 型推論 | タプルの型も推論される。タプルが型推論を可能にしているわけではない |
| 純粋関数型 | 間接的な関係がある。副作用が使えないので、複数の結果は戻り値として 1 つにまとめて返すしかない。そのためタプルの出番が増える |
| 遅延評価 | ほぼ無関係。`zip [1..] xs` のように、無限リストと組み合わせて使えるという程度 |

タプルは Haskell だけのものではない。Python、Rust、Swift、TypeScript などにもあり、静的型付けの言語では同じ理由で必要になる。Haskell らしいのは、「要素の数まで型に含める」「ペアとトリプルは別の型」という厳密さである。その厳密さのおかげで、座標に 3 つ目の数が紛れ込むような誤りが、実行前に見つかる。

</details>

## Ruby との違い

<details>
<summary>Ruby の配列とタプルの比較（原著外の補足）</summary>

Ruby にはタプルという型がない。違う型の値をまとめるときも、配列を使う。

```ruby
person = ["Christopher", "Walken", 55]
```

```haskell
person = ("Christopher", "Walken", 55)
```

| | Ruby の配列 | Haskell のタプル |
|---|---|---|
| 違う型を混ぜる | できる | できる |
| 要素の数 | あとから増減できる | 型で固定される |
| 数の誤り | 実行するまでわからない | コンパイル時に見つかる |
| 1 つ目を取り出す | `pair.first`、`pair[0]` | `fst pair`（ペアのみ） |

Ruby の配列 1 つが、Haskell ではリストとタプルの 2 つに分かれている。

- 同じ種類のものを、いくつでも並べる: リスト
- 違う種類のものを、決まった数だけまとめる: タプル

Ruby では `[1, 2]` と `[8, 11, 5]` を同じ配列に入れられるので、「点は必ず 2 要素」という決まりは、プログラマが守るしかない。Haskell では、その決まりを型に書けば、コンパイラが確かめてくれる。

</details>

<details>
<summary>Ruby の zip と product との比較（原著外の補足）</summary>

`zip` は Ruby にもあり、同じ位置の要素どうしを組にする。違いは 2 つある。

```ruby
[1, 2, 3].zip([5, 5, 5])   # => [[1, 5], [2, 5], [3, 5]]
```

| | Ruby | Haskell |
|---|---|---|
| 結果 | 2 要素の配列の配列 | ペアのリスト |
| 長さが違うとき | レシーバの長さに合わせ、足りない分は `nil` で埋める | 短いほうに合わせ、残りを捨てる |

```ruby
[5, 3, 2, 6].zip(["im", "a"])   # => [[5, "im"], [3, "a"], [2, nil], [6, nil]]
```

Haskell には `nil` に当たる値がなく、ペアの 2 つ目は必ず文字列でなければならない。だから、相手がいない要素は捨てるしかない。

1.5 節で見た Ruby の `product` は、すべての組み合わせを 2 要素の配列にして返す。Haskell では、リスト内包表記の出力にタプルを書けば同じものになる。

```ruby
[2, 5, 10].product([8, 10, 11])
# => [[2, 8], [2, 10], [2, 11], [5, 8], [5, 10], [5, 11], [10, 8], [10, 10], [10, 11]]
```

```haskell
ghci> [(x,y) | x <- [2,5,10], y <- [8,10,11]]
[(2,8),(2,10),(2,11),(5,8),(5,10),(5,11),(10,8),(10,10),(10,11)]
```

`zip` は同じ位置どうしを組にし、`product` と複数の `<-` はすべての組み合わせを作る。

</details>
