# 1.1 関数呼び出し

『すごいHaskellたのしく学ぼう！』第 1 章「はじめの第一歩」の 1.1 節の要約。

## 演算子も関数である

- `*` は、2 つの数を受け取って掛け合わせる
- `49 * 100` のように、2 つの引数のあいだに置いて呼び出す関数を**中置関数**という。
- 数を扱うもの以外の関数は、ほとんどが**前置関数**である。関数名を先に書き、引数をあとに並べる。

<details>
<summary>Ruby の演算子メソッドとの違い（原著外の補足）</summary>

Ruby の `49 * 100` は `49.*(100)` の糖衣構文で、整数オブジェクト `49` の `*` メソッドを、引数 `100` で呼び出している。

```ruby
49 * 100         # => 4900
49.*(100)        # => 4900  同じ意味
49.send(:*, 100) # => 4900
```

「演算子は特別な構文ではなく、普通の関数（メソッド）である」という点は、Haskell と Ruby で共通している。違うのは、その関数が誰のものかである。

| | Ruby | Haskell |
|---|---|---|
| `49 * 100` の正体 | `49` が持つ `*` メソッドに `100` を渡す | `*` という関数に `49` と `100` を渡す |
| 引数の数 | 1 つ（`100`）。`49` はレシーバ | 2 つ（`49` と `100`）。両者は対等 |
| 前置で書くと | `49.*(100)` | `(*) 49 100` |

Ruby では左側の `49` が主役で、「`49` に掛け算を頼む」形になる。Haskell の `*` はどのオブジェクトにも属さない独立した関数で、2 つの引数を同じ立場で受け取る。

この違いは、片方の引数だけを先に渡すときに表れる。

```haskell
ghci> map (* 2) [1, 2, 3]
[2,4,6]
```

`(* 2)` は「2 を掛ける関数」である。`*` が独立した関数なので、引数を 1 つだけ与えた状態で別の関数に渡せる。

</details>

## 関数の呼び出し方

- 多くの命令型言語では、関数名のあとに括弧を書き、引数をカンマで区切る。
- Haskell では、関数名、スペース、引数の順に書く。引数が複数あればスペースで区切る。括弧もカンマも使わない。

```haskell
ghci> succ 8
9
ghci> min 9 10
9
ghci> max 100 101
101
```

- `succ` は、後者（次の値）が定義されているものを受け取り、その後者を返す。
- `min` と `max` は、順序を付けられるものを 2 つ受け取る。`min` は小さいほう、`max` は大きいほうを返す。

## 関数適用は最も優先順位が高い

- 関数適用（関数名のあとにスペースを置いて引数を書くこと）は、すべての演算の中で優先順位が最も高い。
- そのため、次の 2 つの式は同じ意味になる。

```haskell
ghci> succ 9 + max 5 4 + 1
16
ghci> (succ 9) + (max 5 4) + 1
16
```

- 関数適用の範囲を広げたいときは、引数を括弧で囲む。

```haskell
ghci> succ 9 * 10      -- succ 9 を先に計算してから 10 を掛ける
100
ghci> succ (9 * 10)    -- 9 * 10 を先に計算してから succ を適用する
91
```

## バッククォートで中置にする

- 引数を 2 つ取る関数は、バッククォートで囲むと中置関数として呼び出せる。
- `div` は 2 つの整数を受け取り、整数の割り算をする。
- 中置で書くと、どちらをどちらで割るのかが読み取りやすくなる。

```haskell
ghci> div 92 10
9
ghci> 92 `div` 10
9
```

## 括弧の意味は C 系の言語と違う

- 命令型言語の経験者は、括弧を「関数を呼び出す印」と考えがちである。Haskell の括弧は、式をまとめるためだけに使う。

| C 系の言語 | Haskell |
|---|---|
| `foo()` | `foo` |
| `bar(1)` | `bar 1` |
| `baz(3, "haha")` | `baz 3 "haha"` |
| `bar(bar(3))` | `bar (bar 3)` |

- `bar (bar 3)` は、「`bar` に `bar` と `3` の 2 つを渡す」という意味ではない。まず `bar 3` を計算し、その結果を引数にしてもう一度 `bar` を呼ぶ。

<details>
<summary>Ruby の括弧との違い（原著外の補足）</summary>

Ruby の括弧には役割が 2 つある。メソッドの引数を囲む役割と、式をまとめる役割である。Haskell の括弧には、式をまとめる役割しかない。

| | Ruby | Haskell |
|---|---|---|
| 引数を囲む | `bar(1)` | 括弧を使わない |
| 式をまとめる | `(1 + 2) * 3` | `(1 + 2) * 3` |

Ruby は引数を囲む括弧を省略できるので、見た目は Haskell に近くなる。ただし、引数の区切りにはカンマが要る。

| Ruby（括弧あり） | Ruby（括弧なし） | Haskell |
|---|---|---|
| `bar(1)` | `bar 1` | `bar 1` |
| `baz(3, "haha")` | `baz 3, "haha"` | `baz 3 "haha"` |
| `bar(bar(3))` | `bar bar 3` | `bar (bar 3)` |

#### 同じ見た目で意味が違う式

`bar bar 3` は、2 つの言語で解釈が分かれる。

- Ruby は右側から先にまとめて、`bar(bar(3))` と読む。
- Haskell は左から順にまとめて、`(bar bar) 3` と読む。`bar` に関数の `bar` そのものを渡すことになり、型が合わずにエラーになる。

Haskell では引数をスペースで並べるだけなので、どこまでが 1 つの引数かを括弧で示す必要がある。`bar (bar 3)` の括弧はそのためのものである。

#### Ruby で 2 つの役割がぶつかる例

Ruby では、メソッド名と括弧のあいだにスペースを入れるかどうかで、括弧の役割が変わる。

```ruby
puts (1 + 2) * 3   # => 9  括弧は式をまとめる。puts((1 + 2) * 3) と同じ
puts(1 + 2) * 3    # 3 を出力したあと NoMethodError。括弧は引数を囲む。puts の戻り値 nil に 3 を掛けようとする
```

Haskell の括弧は役割が 1 つなので、この種の読み違いが起きない。

</details>
