# 1.3 リスト入門

『すごいHaskellたのしく学ぼう！』第 1 章「はじめの第一歩」の「リスト入門」の節の要約。

## リストとは

- リストは、Haskell で最もよく使うデータ構造である。
- 角括弧で囲み、要素をカンマで区切って書く。

```haskell
ghci> lostNumbers = [4,8,15,16,23,42]
ghci> lostNumbers
[4,8,15,16,23,42]
```

- リストには**同じ型の要素しか入れられない**。数のリストや文字のリストは作れるが、`[1,2,'a',3]` のように数と文字を混ぜることはできない。
- 文字列は文字のリストである。`"hello"` は `['h','e','l','l','o']` の別の書き方にすぎない。そのため、リスト用の関数はすべて文字列にも使える。

<details>
<summary>なぜ、リストの中身はすべて同じ型でなければならないのか（原著外の補足）</summary>

原著は「同じ型の要素しか入れられない」と述べるだけで、理由までは書いていない。

理由は、イントロダクションで挙げた Haskell の特徴から説明できる。

| Haskell の特徴 | リストへの影響 |
|---|---|
| 静的型付け | コンパイル時に、リストのすべての要素の型が決まっていなければならない |
| 型推論 | 要素を見て、コンパイラがリスト全体の型を 1 つに決める |
| 純粋関数型 | 関数は必ず値を返すので、リストから取り出した要素の型も必ず 1 つに決まる |

- Haskell では、リストの型は「何のリストか」まで含めて 1 つに決まる。`[True,False]` の型は `[Bool]`（真偽値のリスト）である。
- 要素の型が 1 つに決まっているから、リストを扱う関数の戻り値の型もコンパイル時に決まる。`[Bool]` に `head` を使えば、結果は必ず `Bool` である。
- 型が混ざることを許すと、`head xs` が数を返すのか文字を返すのかが、実行するまでわからなくなる。それでは、`head xs + 1` のような式が正しいかどうかを、コンパイル時に確かめられない。
- つまり、**型の誤りを実行前にすべて見つけるという約束を守るために、要素の型を 1 つにそろえる**。直接の理由は静的型付けであり、関数型であること自体ではない。

```haskell
ghci> :t [True,False]
[True,False] :: [Bool]
ghci> [1,2,'a',3]
（コンパイルエラー。文字 'a' を数として扱えない）
```

Ruby は実行時に型を調べるので、`[1, "a", nil]` のように型を混ぜた配列を作れる。そのかわり、`[1, "a"].sum` のような誤りは、実行して初めて `TypeError` になる。

</details>

<details>
<summary>文字列は文字のリストである（Ruby との比較、原著外の補足）</summary>

Ruby では文字列は `String` という独立したクラスで、配列ではない。Haskell では、文字列は文字のリストそのものである。

| | Ruby | Haskell |
|---|---|---|
| 文字列の正体 | `String` クラスのオブジェクト | 文字（`Char`）のリスト。`String` は `[Char]` の別名 |
| 1 文字を表す型 | ない。1 文字も `String` | `Char` |
| 引用符 | `'a'` も `"a"` も文字列 | `'a'` は文字、`"a"` は文字列 |
| 配列（リスト）の操作を使う | `"hello".chars` で配列に変換してから | そのまま使える |

```haskell
ghci> "hello" == ['h','e','l','l','o']
True
ghci> :t 'a'
'a' :: Char
ghci> length "hello"
5
ghci> reverse "hello"
"olleh"
```

- この節で出てくる `++`、`:`、`!!`、`head`、`take` などは、すべて文字列にもそのまま使える。文字列専用の関数を別に覚える必要がない。
- 文字列もリストなので、「同じ型の要素しか入れられない」という決まりがそのまま当てはまる。文字列の要素は、すべて `Char` である。

</details>

<details>
<summary>リストの要素はシングルクォートで囲むのか（原著外の補足）</summary>

囲むかどうかは、何を入れるかで決まる。シングルクォートは 1 文字を表す書き方なので、文字のリストを作るときだけ使う。

```haskell
[1, 2, 3]            -- 数のリスト。引用符なし
['a', 'b', 'c']      -- 文字のリスト。シングルクォート
["abc", "de"]        -- 文字列のリスト。ダブルクォート
[True, False]        -- 真偽値のリスト。引用符なし
```

Haskell では、引用符の種類で型が変わる。

| 書き方 | 型 | 意味 |
|---|---|---|
| `'a'` | `Char` | 1 文字 |
| `"a"` | `String` | 文字列（1 文字だけ入った文字のリスト） |

Ruby では `'a'` と `"a"` はどちらも文字列で、違いは式展開できるかどうかだけである。Haskell では別の型なので、混ぜるとエラーになる。

```haskell
['a', "b"]   -- エラー。文字と文字列が混ざっている
'ab'         -- エラー。シングルクォートに入れられるのは 1 文字だけ
```

文字のリストを `['h','e','l','l','o']` と書くことは、実際にはほとんどない。`"hello"` と書けば同じものになる。

</details>

<details>
<summary>Ruby の配列との比較（原著外の補足）</summary>

用途は Ruby の配列と同じで、データを順番に並べて持つために使う。ただし作りが違うので、速い操作がほぼ逆になる。

| | Ruby の配列 | Haskell のリスト |
|---|---|---|
| 作り | 番号の付いた箱が横一列に並ぶ | 各要素が次の要素を指す数珠つなぎ（連結リスト） |
| n 番目を取り出す | 速い（`a[5]`） | 遅い。先頭から順にたどる（`xs !! 5`） |
| 先頭に足す | 中身を後ろへずらす | 一瞬（`:`） |
| 末尾に足す | 速い（`push`、`<<`） | 遅い。最後までたどる（`++`） |
| 長さを調べる | 一瞬（`size`） | 全体をたどって数える（`length`） |
| 要素の型 | 混ぜられる | 同じ型だけ |
| 書き換え | できる（`a[0] = 9`） | できない。新しいリストを作る |

```
Ruby の配列        [ 1 ][ 2 ][ 3 ][   ]
Haskell のリスト   1 → 2 → 3 → 終わり
```

Ruby の配列は後ろに足すのと番号で取り出すのが速く、Haskell のリストは前に足すのと先頭から順に取り出すのが速い。Haskell では、添字で 1 つずつ取り出すのではなく、先頭から順に処理する書き方が基本になる。

</details>

## リストをつなぐ、要素を足す

| 演算子 | 働き | 例 | 結果 |
|---|---|---|---|
| `++` | 2 つのリストをつなぐ | `[1,2,3,4] ++ [9,10,11,12]` | `[1,2,3,4,9,10,11,12]` |
| `++` | 文字列にも使える | `"hello" ++ " " ++ "world"` | `"hello world"` |
| `:` | 先頭に要素を 1 つ足す | `5:[1,2,3,4,5]` | `[5,1,2,3,4,5]` |

- `++` は左側のリストを最後までたどるので、長いリストの末尾に足すと時間がかかる。`:` で先頭に足す操作は一瞬で終わる。
- `++` は 2 つのリストを受け取り、`:` は要素とリストを受け取る。`++` で要素を 1 つ足すときは、`[1,2,3] ++ [4]` のように角括弧で囲む。
- `[1,2,3]` は `1:2:3:[]` の別の書き方である。`[]` は空のリストを表す。

## 要素を取り出す

- `!!` で、番号を指定して要素を取り出す。番号は 0 から始まる。

```haskell
ghci> "Steve Buscemi" !! 6
'B'
```

- 存在しない番号を指定するとエラーになる。

## リストのリスト

- リストの要素にリストを入れられる。内側のリストは、長さが違ってもよいが、型は同じでなければならない。

```haskell
ghci> b = [[1,2,3,4],[5,3,3,3],[1,2,2,3,4],[1,2,3]]
ghci> b !! 2
[1,2,2,3,4]
```

## リストの比較

- 要素どうしを比較できるなら、リストも `<`、`<=`、`>`、`>=`、`==` で比較できる。
- 先頭の要素から順に比べ、同じなら次の要素を比べる（辞書順）。

```haskell
ghci> [3,2,1] > [2,10,100]
True
ghci> [3,4,2] > [3,4]
True
```

<details>
<summary>文字列や、文字列のリストの比較（原著外の補足）</summary>

文字列も、文字列のリストも比較できる。「要素どうしを比較できるなら、リストも比較できる」という決まりが、入れ子でもそのまま働く。

1. 文字（`Char`）は比較できる。
2. 文字列は文字のリストなので、比較できる。
3. 文字列のリストは、比較できるもののリストなので、比較できる。

```haskell
ghci> "abc" < "abd"
True
ghci> ["abc","de"] > ["abc","dd"]
True
ghci> [[1,2],[3]] < [[1,2],[4]]
True
```

2 つ目の例では、1 つ目の要素どうしが同じなので、2 つ目の要素の `"de"` と `"dd"` を比べている。

文字の大小は文字コードの順で決まるので、大文字はすべて小文字より小さい。辞書の並び順とは一致しないことがある。

```haskell
ghci> "Zebra" < "apple"
True
```

比較できないのは、要素が比較できないもののリストである。たとえば関数どうしには大小がないので、関数のリストは比較できない。

Ruby の配列には `>` や `<` がなく、比較には `<=>` を使う。

</details>

## 基本のリスト関数

| 関数 | 働き | 例 | 結果 |
|---|---|---|---|
| `head` | 先頭の要素 | `head [5,4,3,2,1]` | `5` |
| `tail` | 先頭を除いた残り | `tail [5,4,3,2,1]` | `[4,3,2,1]` |
| `last` | 最後の要素 | `last [5,4,3,2,1]` | `1` |
| `init` | 最後を除いた残り | `init [5,4,3,2,1]` | `[5,4,3,2]` |
| `length` | 長さ | `length [5,4,3,2,1]` | `5` |
| `null` | 空かどうか | `null []` | `True` |
| `reverse` | 逆順にする | `reverse [5,4,3,2,1]` | `[1,2,3,4,5]` |
| `take` | 先頭から指定した数だけ取る | `take 3 [5,4,3,2,1]` | `[5,4,3]` |
| `drop` | 先頭から指定した数だけ捨てる | `drop 3 [8,4,2,1,5,6]` | `[1,5,6]` |
| `maximum` | 最大の要素 | `maximum [1,9,2,3,4]` | `9` |
| `minimum` | 最小の要素 | `minimum [8,4,2,1,5,6]` | `1` |
| `sum` | 合計 | `sum [5,2,1,6,3,2,5,7]` | `31` |
| `product` | 積 | `product [6,2,1,2]` | `24` |
| `elem` | 要素が含まれるか | ``4 `elem` [3,4,5,6]`` | `True` |

- `head`、`tail`、`last`、`init` を空のリストに使うと、実行時にエラーになる。この誤りはコンパイル時には見つからない。
- リストが空かどうかは、`xs == []` ではなく `null xs` で調べる。
- `take` は、要素の数より多く指定するとリスト全体を返す。
- `elem` は、ふつう中置で書く。
