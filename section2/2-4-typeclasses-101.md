# 2.4 型クラス 初級講座

『すごいHaskellたのしく学ぼう！』第 2 章「型を信じろ！」の 2.4 節の要約。

## 型クラスとは

- **型クラス**は、何らかの振る舞いを定義するインターフェースである。ある型が型クラスに属していれば、その型は、型クラスが定める振る舞いを備えている。
- オブジェクト指向言語のクラスとは別のものである。Java のインターフェースに近い。

```haskell
ghci> :t (==)
(==) :: Eq a => a -> a -> Bool
```

- `=>` より前の部分を、**型クラス制約**という。
- この型は、「同じ型の値を 2 つ受け取って `Bool` を返す。ただし、その型は `Eq` 型クラスに属していなければならない」と読む。
- `==` のように記号だけでできた関数の型を調べるときや、前置で呼び出すときは、丸括弧で囲む。

<details>
<summary>型クラスの中身と、文字列の型クラスがない理由（原著外の補足）</summary>

値が型に属するように、型が型クラスに属する。`5` は `Int` に属し、`Int` は `Eq` に属する。

型クラスに書いてあるのは、属する型の一覧ではなく、**用意すべき関数の一覧**である。関数の中身は、型ごとの `instance` 宣言に書く。`class` と `instance` の書き方は、原著では第 7 章で扱う。

| 書く場所 | 書いてあること |
|---|---|
| `class Eq a where ...` | `Eq` に属するなら `==` と `/=` を用意すること |
| `instance Eq Int where ...` | `Int` は `Eq` に属する。`Int` の `==` の中身 |

- `3 + 4` と書くと、コンパイラが型を見て、その型の `+` を選ぶ。
- どの型が属しているかは、`instance` 宣言を集めた結果として決まる。自分で作った型も、`instance` を書けばあとから属させられる。ghci の `:info Eq` で一覧を見られる。
- 型クラスは既定の実装を持てる。`Eq` の `/=` は「`==` の否定」と決まっているので、型ごとに書くのは `==` だけでよい。Ruby の `Comparable` が `<=>` から `<` や `>` を作るのと同じ形である。
- Ruby でも、`Comparable` の中に取り込んだクラスの一覧はなく、各クラスが `include Comparable` と宣言する。

文字列の型クラスは、標準にはない。`Num` があるのは、数の型が `Int`、`Integer`、`Float`、`Double` と複数あり、`+` や `*` を共通で使いたいからである。標準の文字列は `String`（`[Char]`）の 1 つだけなので、まとめる必要がない。`String` は型であり、`Eq`、`Ord`、`Show`、`Read` に属している。

`Show` は「文字列に変換できる型」の型クラスであり、文字列の型クラスではない。

</details>

## 基本の型クラス

| 型クラス | 振る舞い | 主な関数 |
|---|---|---|
| `Eq` | 等しいかどうかを調べられる | `==`、`/=` |
| `Ord` | 順序を付けられる | `>`、`<`、`>=`、`<=`、`compare` |
| `Show` | 文字列として表せる | `show` |
| `Read` | 文字列から値を作れる | `read` |
| `Enum` | 順番に並べられる | `succ`、`pred`、レンジ |
| `Bounded` | 上限と下限がある | `minBound`、`maxBound` |
| `Num` | 数として振る舞える | `+`、`*` など |
| `Integral` | 整数だけ。`Int` と `Integer` | |
| `Floating` | 小数だけ。`Float` と `Double` | |

### Eq と Ord

- これまでに出てきた型は、関数を除いてすべて `Eq` と `Ord` に属している。
- `Ord` に属するには、先に `Eq` に属していなければならない。
- `compare` は 2 つの値を比べ、`GT`（より大きい）、`LT`（より小さい）、`EQ`（等しい）のいずれかを返す。この 3 つの値の型は `Ordering` である。

```haskell
ghci> "Abrakadabra" `compare` "Zebra"
LT
ghci> 5 `compare` 3
GT
```

### Show と Read

- `show` は値を文字列にし、`read` は文字列から値を作る。

```haskell
ghci> show 3
"3"
ghci> read "8.2" + 3.8
12.0
ghci> read "[1,2,3,4]" ++ [3]
[1,2,3,4,3]
```

- `read` の結果は、そのあとの使われ方から型が決まる。`+ 3.8` が続けば小数、`++ [3]` が続けば数のリストになる。
- `read "4"` とだけ書くと、何の型にすればよいかをコンパイラが決められない。このときは、式のあとに `::` と型を書いて、型を明示する。これを**型注釈**という。

```haskell
ghci> read "5" :: Int
5
ghci> read "5" :: Float
5.0
ghci> read "[1,2,3,4]" :: [Int]
[1,2,3,4]
```

### Enum と Bounded

- `Enum` に属する型は、レンジに使える。`succ` で次の値、`pred` で前の値が得られる。

```haskell
ghci> [LT .. GT]
[LT,EQ,GT]
ghci> succ 'B'
'C'
```

- `minBound` と `maxBound` は、型によって値が変わる。型注釈でどの型の上限、下限かを指定する。

```haskell
ghci> minBound :: Int
-9223372036854775808
ghci> maxBound :: Bool
True
```

### Num、Integral、Floating

- 整数のリテラルは、`Num` に属するどの型としても振る舞える。

```haskell
ghci> :t 20
20 :: Num a => a
ghci> 20 :: Float
20.0
```

- `*` の型は `Num a => a -> a -> a` である。2 つの引数は同じ型でなければならない。`(5 :: Int) * (6 :: Integer)` は型エラーになる。
- 整数と小数を混ぜて計算したいときは、`fromIntegral` で整数をより一般的な数に変換する。

```haskell
ghci> length [1,2,3,4] + 3.2
（型エラー。length は Int を返すので、小数と足せない）
ghci> fromIntegral (length [1,2,3,4]) + 3.2
7.2
```

## Ruby との違い

<details>
<summary>型クラスと Ruby のモジュール（原著外の補足）</summary>

型クラスに近いものは、Ruby では 2 つある。

1 つ目は、**ダックタイピング**である。Ruby では、`==` や `<=>` や `to_s` を持っていれば、どんなオブジェクトでも比較や文字列化に使える。「このメソッドを持っているものなら何でもよい」という考え方は、型クラス制約と同じである。

2 つ目は、**モジュール**である。`Comparable` を取り込んで `<=>` を定義すると、`<`、`>`、`between?` などがまとめて使えるようになる。

| Haskell の型クラス | Ruby で近いもの |
|---|---|
| `Eq` | `==` メソッド |
| `Ord` | `Comparable` モジュールと `<=>` |
| `Show` | `to_s`、`inspect` |
| `Read` | `to_i`、`to_f`、`Integer("5")` |
| `Enum` | `succ`、`Range` |
| `Num` | `Numeric` クラス |

`compare` は、Ruby の `<=>` に当たる。返す値が違うだけである。

```ruby
5 <=> 3   # => 1   （1、0、-1 のいずれか）
```

```haskell
ghci> 5 `compare` 3
GT
```

いちばん大きな違いは、確かめる時である。

- Ruby は、メソッドを呼んだ時点で、そのオブジェクトがメソッドを持っているかを調べる。持っていなければ、実行時に `NoMethodError` になる。
- Haskell は、`Eq a =>` のような型クラス制約をコンパイル時に確かめる。等しいかどうかを調べられない型の値を `==` に渡す呼び出しは、コンパイルできない。

</details>

<details>
<summary>read と、Ruby の to_i の違い（原著外の補足）</summary>

Ruby では、文字列を何に変換するかを、メソッドの名前で選ぶ。

```ruby
"5".to_i   # => 5
"5".to_f   # => 5.0
```

Haskell の `read` は 1 つの関数で、何に変換するかは、結果に求められる型で決まる。

```haskell
ghci> read "5" :: Int
5
ghci> read "5" :: Float
5.0
```

同じ `read "5"` が、求められる型によって違う値を返す。**戻り値の型によって関数の動作が変わる**というのは、Ruby にはない考え方である。`minBound` や `maxBound` も同じで、`minBound :: Int` と `minBound :: Bool` は違う値になる。

変換に失敗したときの動きも違う。Ruby の `"abc".to_i` は `0` を返す。Haskell の `read "abc" :: Int` は、実行時にエラーになる。

</details>
