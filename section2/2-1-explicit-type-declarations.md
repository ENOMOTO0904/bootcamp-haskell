# 2.1 明示的な型宣言

『すごいHaskellたのしく学ぼう！』第 2 章「型を信じろ！」の 2.1 節の要約。

## 型とは

- Haskell は静的型付けである。すべての式の型がコンパイル時にわかっているので、真偽値を数で割るような誤りは、実行する前に見つかる。
- 型推論があるので、型をいちいち書く必要はない。それでも、型の仕組みを理解することは Haskell を学ぶうえで欠かせない。
- **型**は、式がどの種類に属するかを示す札である。`True` は真偽値、`"hello"` は文字列である。
- `ghci` で `:t` のあとに式を書くと、その式の型がわかる。`::` は「の型は」と読む。

```haskell
ghci> :t 'a'
'a' :: Char
ghci> :t True
True :: Bool
ghci> :t "HELLO!"
"HELLO!" :: String
ghci> :t (True, 'a')
(True, 'a') :: (Bool, Char)
ghci> :t 4 == 5
4 == 5 :: Bool
```

- 型の名前は、必ず大文字で始まる。
- `String` は `[Char]`（文字のリスト）の別名である。
- タプルは、要素の数と、それぞれの型によって型が決まる。

<details>
<summary>Ruby の型は「どのクラスから作られたか」で決まる（原著外の補足）</summary>

Ruby にも型はある。Ruby で型を調べるには、値に `class` を聞く。

```ruby
"a".class    # => String
1.class      # => Integer
1.5.class    # => Float
true.class   # => TrueClass
```

Ruby では、すべての値がオブジェクトであり、オブジェクトは必ずどれかのクラスから作られる。`"a"` という書き方は、`String.new("a")` と同じように、`String` クラスからオブジェクトを 1 つ作っている。

```ruby
String.new("a")         # => "a"
String.new("a").class   # => String
```

つまり、Ruby で「これは文字列か、数か」を決めているのは、**その値がどのクラスから作られたか**である。値は、自分を作ったクラスを覚えていて、`class` と聞かれるとそれを答える。

Haskell の `:t` も型を調べるものだが、聞いている相手が違う。

| | Ruby の `class` | Haskell の `:t` |
|---|---|---|
| 聞く相手 | 実行して出来上がった値 | 実行する前の式 |
| 型の持ち主 | 値（オブジェクト） | 式 |
| 型の決まり方 | どのクラスから作られたか | 式の書き方から、コンパイラが割り出す |
| わかる時 | 実行時 | コンパイル時 |

違いは、計算を含む式で表れる。

```ruby
(1 + 2).class   # => Integer   1 + 2 を計算して 3 を作り、その 3 に聞く
```

```haskell
ghci> :t 4 == 5
4 == 5 :: Bool
```

Ruby は、まず式を実行して値を作り、その値にクラスを聞く。Haskell の `:t` は、式を実行しない。`4 == 5` を計算しなくても、「`==` の結果は `Bool` である」ことが式の形からわかる。

実行しないことは、無限リストで確かめられる。

```haskell
ghci> :t length [1..]
length [1..] :: Int
```

`length [1..]` は実行すると終わらないが、型はすぐに返ってくる。Haskell の型は、値ができる前から式に付いている。

</details>

## 関数の型宣言

- 関数にも型がある。関数を定義するときに、型を明示的に宣言できる。短い関数を除いて、宣言を書くのがよい習慣とされる。

```haskell
removeNonUppercase :: String -> String
removeNonUppercase st = [ c | c <- st, c `elem` ['A'..'Z']]
```

- `String -> String` は、「文字列を受け取って、文字列を返す」と読む。

```haskell
addThree :: Int -> Int -> Int -> Int
addThree x y z = x + y + z
```

- 引数が複数あるときも、すべて `->` で区切る。**最後の 1 つが戻り値の型で、それより前が引数の型である。** `addThree` は、`Int` を 3 つ受け取って `Int` を返す。
- 型宣言の書き方がわからないときは、宣言を書かずに関数を定義し、`:t` で調べればよい。

<details>
<summary>型宣言は入力と出力の型を固定する（原著外の補足）</summary>

型宣言は、関数に入れられるものと、出てくるものを、型で固定する。

```
addThree :: Int -> Int -> Int -> Int
            └───── 入力 ─────┘    └ 出力
```

固定すると、関数を実行しなくても、3 か所の誤りがコンパイル時に止まる。

| どこの誤りか | 例 | 止まる理由 |
|---|---|---|
| 呼び出す側 | `addThree 1 "b" 3` | 2 つ目の引数が `Int` でない |
| 関数の中身 | `Int` を返すと宣言して、文字列を返す | 中身が宣言と合わない |
| 結果を使う側 | `addThree 1 2 3 ++ "円"` | 結果は `Int` なので、文字列とつなげられない |

1.2 節の「関数は必ず値を返す」に、「どの型の値を返すかも決まっている」が加わる。

宣言を書かなくても、型は固定されている。型推論によって、コンパイラが型を付けるからである。宣言を省いた `addThree` は、数なら何でも受け取る関数になる。

```haskell
ghci> :t addThree
addThree :: Num a => a -> a -> a -> a
ghci> addThree 1.5 2 3
6.5
```

宣言を書くと、「`Int` だけを受け取るつもりだ」という意図が加わり、小数を渡す呼び出しも止められる。宣言は、型を付けるためのものではなく、自分の意図をコンパイラに伝えて確かめてもらうためのものである。

固定しすぎたくないときは、型変数を使う（2.3 節）。

</details>

<details>
<summary>Ruby のメソッドには型宣言がない（原著外の補足）</summary>

Ruby のメソッドは、引数の型を宣言しない。何が渡されるかは、実行するまでわからない。

```ruby
def add_three(x, y, z)
  x + y + z
end

add_three(1, 2, 3)        # => 6
add_three("a", "b", "c")  # => "abc"
add_three(1, "b", 3)      # 実行して初めて TypeError
```

```haskell
addThree :: Int -> Int -> Int -> Int
addThree x y z = x + y + z
```

Ruby の `add_three` は、`+` が使えるものなら何でも受け取る。Haskell の `addThree` は、`Int` を 3 つ受け取ると宣言しているので、文字列を渡す呼び出しはコンパイルの時点で止まる。

型宣言は、コンパイラのための検査項目であると同時に、読む人のための説明書でもある。`Int -> Int -> Int -> Int` を見れば、中身を読まなくても、何を渡して何が返るかがわかる。

</details>
